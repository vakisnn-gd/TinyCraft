# TinyCraft v0.2.1: проверка перед публикацией

Цель: за один короткий проход найти критические поломки до загрузки ZIP в GitHub Releases.

## Короткий обязательный чек-лист

- [ ] Исходники компилируются, `run-tests.bat` завершает 108 тестов с `OK`.
- [ ] Новый singleplayer-мир запускается; берег, океан и чанки вокруг игрока отображаются без дыр.
- [ ] Урон, смерть при `0 HP`, голод, еда и естественная регенерация работают.
- [ ] `F2`, `F3`, `F3 + G`, `F5`, `F6` и панорама главного меню работают при разных масштабах GUI.
- [ ] Dedicated server принимает два клиента через `127.0.0.1:25566`.
- [ ] Блоки, inventory, containers, команды, item drop и reconnect синхронизируются.
- [ ] `save`, `stop` и повторный запуск сохраняют мир и игроков.
- [ ] `TinyCraft-v0.2.1-windows.zip` запускается из чистой папки и не содержит saves/logs/profile.

Если любой пункт не пройден, релиз не публиковать: записать проблему в `KNOWN_ISSUES.md` или исправить её и повторить проверку.

## 1. Автоматическая проверка

```bat
javac -encoding UTF-8 --release 8 -cp "lib/*" -d out *.java
.\run-tests.bat
```

Ожидание: компиляция проходит, JUnit показывает `OK (108 tests)`.

## 2. Новый мир и океан

- Создать новый survival-мир, не использовать старые сохранённые чанки.
- Осмотреть берег, мелководье и океан; проплыть или пролететь минимум через 10-15 чанков.
- Проверить, что низкий берег заполнен водой до уровня моря, а `seagrass`/`kelp` находятся внутри воды.
- Убедиться, что при догрузке нет устойчивых дыр и зависших отдельных островов mesh.

Ожидание: мир остаётся проходимым, вода не заменена песком до уровня моря. Ступенчатые переходы и слабая анимация воды допустимы и перечислены в `KNOWN_ISSUES.md`.

## 3. Survival

- Получить урон и убедиться, что здоровье уменьшается.
- При hunger не ниже 18 дождаться естественной регенерации: здоровье растёт, скрытый запас сытости расходуется раньше видимой полоски.
- Побегать: hunger не должен уменьшаться чаще одного шага примерно за 20 секунд непрерывного спринта.
- После исчерпания защиты проверить уменьшение видимого hunger и урон от голода при пустой полоске.
- Получить смертельный урон: при `0 HP` должен открыться экран смерти; после respawn здоровье и hunger восстановлены.

## 4. Интерфейс и снимки

- Нажать `F2`: в `screenshots/` появляется читаемый PNG и сообщение с путём.
- Открыть `F3`: слева видны версия, FPS, координаты и мир; справа - система, память и данные чанка.
- Проверить маленький и большой GUI scale: строки не выходят за экран, правая колонка заканчивается у правого края, общей чёрной подложки нет.
- Проверить `F3 + G`, закрытие `F3` и отсутствие повторного переключения при удержании клавиши.
- Нажать `F6`: создаётся папка с `panorama_0.png` - `panorama_5.png`, позиция и направление игрока после съёмки не меняются.
- Скопировать шесть файлов в `assets/menu_panorama/`, перезапустить игру и проверить панораму главного меню.

## 5. Dedicated server и два клиента

```bat
.\run-server.bat
.\run-game.bat
```

В обоих клиентах: Multiplayer -> Direct IP -> `127.0.0.1:25566`. Для второго клиента использовать другой UUID/profile.

Ожидание:

- оба игрока появляются на безопасной поверхности и видят друг друга;
- рядом нет больших незагруженных дыр после loading screen;
- Tab показывает обоих игроков, ping и здоровье;
- server log не показывает поток ошибок или rate-limit сообщений при обычной игре.

## 6. Блоки, предметы и контейнеры

- Поставить и сломать dirt, wood и stone; проверить результат вторым клиентом.
- Выбросить и подобрать item; убедиться, что он не дюпается.
- Открыть chest, furnace и crafting table; проверить left/right click, shift-click и закрытие через Esc.
- Вторым клиентом сломать открытый container.
- В creative взять stack, положить его в hotbar и поставить несколько блоков.

Ожидание: нет ghost-блоков, частичных inventory-изменений, дюпа или исчезновения предметов; сломанный container закрывается или становится неактивным.

## 7. Команды и права

Проверить из server console и чата оператора:

```text
give <player> dirt 64
gamemode creative <player>
tp <player> 0 90 0
clear <player>
gamemode survival <player>
```

Ожидание: команды применяются на сервере, обычный игрок без cheats/op не получает доступ к gameplay-командам, подсказки используют namespace `tinycraft:`.

## 8. Сохранение и повторный вход

- Изменить мир, позицию, inventory и container.
- Выполнить `save`, затем `stop`.
- Перезапустить сервер и войти теми же профилями.

Ожидание: мир, контейнеры, позиции и inventory сохранены; сервер не оставил повреждённых временных файлов.

## 9. Финальный ZIP

```bat
.\build-release.bat
```

- Проверить имя `release/TinyCraft-v0.2.1-windows.zip`.
- Распаковать ZIP в новую пустую папку и запустить `run-game.bat`.
- Проверить версию `0.2.1` в `F3` и запуск без исходников/IDE.
- Убедиться, что внутри нет `saves/`, `logs/`, `screenshots/`, `profile.properties`, `server.properties`, `.vscode/` и случайных `.class` вне `out/`.
- Для GitHub Releases использовать tag `v0.2.1` и asset `TinyCraft-v0.2.1-windows.zip`.
